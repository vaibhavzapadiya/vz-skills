Start with `npx vz-skills doctor`. It checks Node, Claude Code, the install, and your config.
</Lead>

| Problem | Cause | Fix |
|---|---|---|
| Skills show up twice | A flat install and a plugin install are both active | Remove one with `npx vz-skills uninstall --flat` or `npx vz-skills uninstall` |
| `/vz-skills:` does not autocomplete | The plugin is not loaded | Run `claude plugin list`, then `/reload-plugins` |
| "Claude Code CLI not found" | `claude` is not on `PATH` in that shell | Open a shell where `claude --version` works |
| Install cannot register the marketplace | A `vz-skills-marketplace` already exists from another path | `claude plugin marketplace remove vz-skills-marketplace`, then install again |
| Flat install stops: "not created by vz-skills" | You have your own skill or agent with the same name. Nothing was changed. | Rename yours, or pass `--force` (yours is backed up to `vz-skills-backups/` first) |
| Flat install says `settings.json` is not valid JSON | The file named in the message has a syntax error. Nothing was changed. | Fix the file, then run it again |
| `update` or `uninstall` says it is not installed | You installed with `--scope project` or `local`, and the default is `user` | Pass the same `--scope` you installed with |
| `update --flat` says flat installs exist in several scopes | You have a flat install at user scope and another in this project | Pass `--scope` for the one to update |
| A `vz-skills` command exits with "unknown option" | A misspelled flag. Flags are strict. | Check `npx vz-skills help`. Nothing ran. |
| `git push` or `gh pr create` asks first | Expected: anything that leaves your machine asks | Confirm, or set `approvals.external_actions: "refuse"` to deny |
| `find . -delete` is denied | A `find -delete` with no filter, starting at `.` or another root, deletes everything under it | Add a filter such as `-name '*.tmp'` (then it asks) |
| A guard asks "too large to inspect" | The command is over 32 KB, or the input over 2 MB | Confirm it, or split it up |
| Turning a guard off in the project config does nothing | Only your own `~/.vz-skills/config.json` can acknowledge that | Acknowledge it there, if you mean it |
| `/status` shows Claude's status, not VZ's | Expected after a flat install | Use `/vz-status` |
| Every command asks for confirmation | The command guard matched something, such as `sudo` or `rm -r` | Read the prompt; it names the reason. Change the command or your settings. |
| A command is denied | It matched a catastrophic pattern | Run it yourself in a terminal if you are sure |
| No session brief at start | `hooks.session_context` is false, or hooks are disabled | Run `/vz-status` |
| `vz-config.js` exits with 1 | A config error | Read the `ERROR:` lines. Each names the key and the fix. |
| A command is `UNKNOWN` | Nothing in your manifest, Makefile or CI names it | Tell Claude the command, or add a script. It will not guess. |
| Baseline is `BLOCKED` | The test command is not a well-known form | Run it yourself, or add a standard script |

## Debugging

```bash
claude --debug                                              # shows hooks and skill loading
node plugins/vz-skills/scripts/vz-config.js --explain --project .
node plugins/vz-skills/scripts/vz-discover.js . --format md
```
