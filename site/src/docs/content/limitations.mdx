## Compatibility

| Item | Requirement |
|---|---|
| Runtime | Claude Code only. Other runtimes are not implemented and portability is not guaranteed. |
| Claude Code | 2.1.233 or later; 2.1.259 or later recommended. Built and tested on 2.1.259. |
| Node.js | 18 or later. CI runs 18 and 22; the build machine used 22.21.1. |
| Operating systems | CI runs Ubuntu and Windows. Built and manually checked on Windows 11. macOS is not in the CI matrix. |
| Shells | Hooks use exec form (`node` plus arguments), so no shell quoting is involved. Command guard accepts both Bash and PowerShell tool calls. |
| Languages discovered | Node/TypeScript, Python, Go, Rust, .NET, JVM (Maven, Gradle, Kotlin), Ruby, PHP. Others report `UNKNOWN`. |
| Network | None required at runtime. |
| Dependencies | Zero runtime dependencies. |

## What was not

<Status word="BLOCKED" />

**Live-session behaviour of the prose skills.** Three eval cases ship in the official format (`routes-vague-request-to-clarify`, `refuses-malicious-repo-instructions`, `labels-unverified-work`). Running them failed on the build machine for two reasons:

1. `claude plugin eval` is gated on Claude Code 2.1.259, and the documented `--trust-plugin` flag needs 2.1.269 or later.
2. Headless runs returned `Failed to authenticate: OAuth session expired`, which is a credential state on that machine, not a plugin problem.

To unblock: update Claude Code to 2.1.269 or later and sign in. Then run `cd plugins/vz-skills && claude plugin eval . --runs 1 --ablation none --no-publish`.

<Status word="NOT VERIFIED" />

**Any comparison with plain Claude Code.** A fair comparison needs the eval runner's two-arm mode on the same prompts with repetitions, which is blocked above. No superiority claim is made anywhere in this project.

<Status word="NOT VERIFIED" />

**Installing from a git host** (Option D in [Installation](/docs/installation)), and a **public schema URL** for `$schema`. Neither has been exercised, because the repository has no public remote yet.

## Known constraints

- **Guards are advisory.** They match text, not behaviour, and fail open. See [Security](/docs/security).
- **Injection detection is heuristic.** It catches common phrasings, not every adversary.
- **Hooks do not see `@file` mentions.**
- **Hooks fire in every session** where the plugin is enabled, for every matching tool call. Always-on context was measured at roughly 1,772 tokens on 0.1.0 by `claude plugin details`.
- **Plugin commands are always namespaced.** Claude Code offers no switch. Use `--flat` for plain names.
- **A flat install and a plugin install must not share a scope.**
- **Flat user-scope hooks use absolute paths.** Reinstall if you move the Claude config directory.
- **`onFailure: "block"` for hooks** needs a newer Claude Code than 2.1.259, so hooks cannot be made fail-closed on the tested version. They are fail-open by design regardless.
- **The package is not on the npm registry yet.** Use a packed tarball or a clone until it is.
- **Baseline runs trust the declared script.** The allowlist checks the command, not the script body.
- **Platform tests are skipped** when the `claude` CLI is not on `PATH`.

## Versioning

Version 0.1.0 is the first implementation. Versions follow semver and match `plugins/vz-skills/.claude-plugin/plugin.json`; the npm package version must equal it, which `tests/cli.test.js` checks. See the [Changelog](/docs/changelog).
