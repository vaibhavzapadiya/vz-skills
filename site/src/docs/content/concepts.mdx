## Evidence labels

Every fact and every claim carries a label, so you can see how sure Claude is.

**Facts about your repository**

| Label | Meaning |
|---|---|
| <Status word="CONFIRMED" /> | Read directly from a file or command. The source is named. |
| <Status word="INFERRED" /> | Follows from a convention. The reason is stated. |
| <Status word="UNKNOWN" /> | Nothing established it. Claude asks instead of guessing. |
| <Status word="CONFLICTING" /> | Two sources disagree. Both are shown. |

**Claims about the work**

| Label | Meaning |
|---|---|
| <Status word="IMPLEMENTED" /> | The files exist. |
| <Status word="TESTED" /> | A check ran after the last edit and the result was seen. |
| <Status word="VERIFIED" /> | A requirement is met, with evidence. |
| <Status word="BLOCKED" /> | Cannot continue. The reason is given. |
| <Status word="NOT VERIFIED" /> | No evidence. "Should work" lands here. |

## Profiles

A profile sets how careful Claude is.

| | `FAST` | `BALANCED` (default) | `PRODUCTION` |
|---|---|---|---|
| Write a plan when risk is | high | medium or above | always |
| Tests to run | changed units | plus everything that imports them | whole suite, lint, typecheck |
| Record a baseline first | no | yes | yes |
| Independent reviewer | never | medium or high risk | always |
| Security review | sensitive paths | material changes | every change |
| Final report | summary | evidence table | full |

## Risk tiers

- **Low.** Docs, comments, formatting, test-only changes.
- **Medium.** A new feature, a bug fix, a refactor inside one module.
- **High.** Auth, payments, migrations, infrastructure, secrets, deletes.

Anything that touches auth, payments, migrations, infrastructure or secrets is high, whatever the profile.

## How a request flows

Claude picks the steps a request needs. A one-line fix skips most of them.

1. **Discover.** Read the repository: stack, commands, tests, git state.
2. **Clarify.** Write 3 to 8 checkable acceptance criteria.
3. **Plan.** Split the work into slices, each with a test and a command to check it.
4. **Implement.** One slice at a time, smallest change first.
5. **Test.** Record a baseline, then run the tests that matter.
6. **Review.** Ranked findings. A security review runs when the risk calls for it.
7. **Verify.** Re-run the checks and write the report.

If something fails, `debug` finds the root cause before any fix is made.

## Discovery

Discovery is plain code, not a prompt. It reads manifests, lockfiles, CI files and git, and labels each fact.

- It runs no project scripts. With `--baseline` it runs your test command once, only if it is a well-known form such as `npm test` or `pytest`.
- It never opens `.env` files or keys.
- It scans instruction files like `CLAUDE.md` and flags text that tries to steer Claude. That text is treated as data, never as orders.
- Anything it cannot establish stays `UNKNOWN`.
