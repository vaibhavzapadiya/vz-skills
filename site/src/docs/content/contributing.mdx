## Local development

```bash
git clone <this repo> && cd VZ-skills
npm test                                   # all suites, no installs, no network
claude plugin validate ./plugins/vz-skills --strict
claude --plugin-dir ./plugins/vz-skills    # try it in a session
```

Most `SKILL.md` edits apply without restarting (`/reload-skills`). Hook or manifest changes need `/reload-plugins` or a new session.

Everything a user receives lives under `plugins/vz-skills/`; tests, fixtures, docs and this site are not shipped in the npm package.

## Rules of the road

- **Verify platform claims against the current Claude Code docs.** Record the page and access date in `docs/decisions.md` when you rely on a new platform detail.
- **Keep `SKILL.md` under about 200 lines.** Put detail in `references/` and link it with `${CLAUDE_PLUGIN_ROOT}/references/...`.
- **No new runtime dependencies** without a decision entry in `docs/decisions.md`.
- **Every behaviour change in scripts needs a test.** Every bug fix needs a regression test.
- **Generated docs stay generated.** Run `node scripts/gen-catalog.js` after changing skill or agent frontmatter, and `node scripts/gen-config-schema.js` after changing `SCHEMA` in `lib/config.js`. `npm test` fails if either is stale, and if a config key is undocumented.
- **Status words are exact:** IMPLEMENTED, TESTED, VERIFIED, BLOCKED, NOT VERIFIED.

## Adding a skill

1. Create `plugins/vz-skills/skills/<group>/<kebab-name>/SKILL.md` with frontmatter. The group is `entry`, `lifecycle`, `specialists`, or `productivity`. A new group folder must also be listed in the `skills` array of `plugin.json`, or its skills silently fail to load. `npm test` and `vz-validate.js` catch that; the official validator does not. `name` equals the directory, `description` is specific and starts with the key use case, and `disable-model-invocation: true` marks user-only commands.
2. Write the body: purpose, inputs, workflow with decision points, output shape, safety, failure behaviour, validation scenarios.
3. Run `node plugins/vz-skills/scripts/vz-validate.js plugins/vz-skills` and `claude plugin validate ./plugins/vz-skills --strict`.
4. Run `node scripts/gen-catalog.js` and add a changelog entry.
5. Add an eval case under `plugins/vz-skills/evals/` if the behaviour can be judged from a read-only run.
6. Update `site/src/data/skills.ts` so this site lists it. `npm run check` in `site/` fails if the counts disagree.

## Adding a config key

Extend `SCHEMA` (and `floor` if it needs one) in `lib/config.js`, add a row to `docs/configuration.md`, run `node scripts/gen-config-schema.js`, and update the table in `site/src/docs/content/configuration.mdx`. The config test asserts presets are schema-valid and the docs test asserts every key is documented.

## Adding a hook

Declare it in `hooks.json`, implement it with `lib/hookio.js`, and add fail-open and decision tests.

## Releasing

1. Update `version` in `plugins/vz-skills/.claude-plugin/plugin.json` and `package.json`, and add the entry to `CHANGELOG.md`.
2. Run `npm test`, `claude plugin validate ./plugins/vz-skills --strict`, and `node scripts/gen-catalog.js --check`.
3. Run `npm run package`. It builds `dist/vz-skills-<version>.zip` and verifies its integrity.
4. Update `docs/testing-and-evaluation.md` with this release's observed results.
5. Tag with `claude plugin tag ./plugins/vz-skills` if you publish through a git marketplace. Push only with the owner's authorization.
6. Publishing to npm is owner-only. Set `repository` and `homepage` in `package.json` first, then `npm pack`, which runs `prepack`. Test the tarball with `npx --yes ./vz-skills-<version>.tgz doctor`.

## Working on this website

```bash
cd site
npm install
npm run dev       # http://localhost:5173
npm run verify    # typecheck, content checks, production build
```

Site content under `site/src/docs/content/` is MDX. Values copied from the plugin (the profile matrix, the skill list, sample output) are in `site/src/data/` and should be updated with the plugin. `npm run check` compares the skill count, hook count, profile matrix and install commands against the plugin's own files.

## Reporting issues

Include the Claude Code version, OS, the skill or hook involved, the command or prompt, observed versus expected behaviour, and `vz-config.js --explain --project .` output with secrets redacted.
