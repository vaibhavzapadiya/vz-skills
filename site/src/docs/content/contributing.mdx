## Run it locally

```bash
git clone https://github.com/vaibhavzapadiya/vz-skills.git && cd vz-skills
npm test                                     # all suites, no installs, no network
claude plugin validate ./plugins/vz-skills --strict
claude --plugin-dir ./plugins/vz-skills      # try it in a session
```

## Submitting changes

`main` is protected: nobody pushes to it directly except the maintainer. Every other change goes through a pull request:

1. Fork the repository on GitHub, clone your fork, and create a branch for your change:

   ```bash
   git clone https://github.com/<your-user>/vz-skills.git && cd vz-skills
   git checkout -b fix/short-description
   ```

2. Make the change with its test, then run `npm test` and `claude plugin validate ./plugins/vz-skills --strict`.
3. Push the branch to your fork and open a pull request against `main` in [vaibhavzapadiya/vz-skills](https://github.com/vaibhavzapadiya/vz-skills).

A pull request can merge when all four CI jobs pass (Ubuntu and Windows, Node 18 and 22) and the maintainer has approved it. Pushing new commits to the branch clears an earlier approval. Force-pushing to `main` and deleting it are blocked for everyone.

## Layout

```text
plugins/vz-skills/    the installable plugin
  skills/<group>/<name>/SKILL.md   groups: entry, lifecycle, specialists, productivity
  agents/  hooks/  policy/  references/  schema/  scripts/  evals/
bin/                  the npx installer
tests/  fixtures/     the test suites and sample repositories
docs/                 documentation, decision log, config examples
site/                 this website
```

## Rules

- Keep each `SKILL.md` under about 200 lines. Put detail in `references/`.
- No new runtime dependencies without an entry in `docs/decisions.md`.
- A script change needs a test. A bug fix needs a regression test.
- After changing skill frontmatter, run `node scripts/gen-catalog.js`. After changing the config schema, run `node scripts/gen-config-schema.js`. `npm test` fails if either is stale.

## Add a skill

1. Create `plugins/vz-skills/skills/<group>/<name>/SKILL.md`. The folder name is the skill name.
2. If you add a new group folder, list it in the `skills` array of `plugin.json`. Without that, its skills silently do not load.
3. Run `node plugins/vz-skills/scripts/vz-validate.js plugins/vz-skills` and `node scripts/gen-catalog.js`.
4. Add the skill to `site/src/data/skills.ts`. `npm run check` in `site/` fails if it is missing.

## Release

Update the version in `plugin.json` and `package.json`, add a `CHANGELOG.md` section for it, run `npm test` and `claude plugin validate ./plugins/vz-skills --strict`, push to `main`, then push a tag `vX.Y.Z`. The release workflow checks the versions, runs the tests, stages the package on npm with provenance, and creates the GitHub release; the maintainer then makes it public with `npm stage approve vz-skills@X.Y.Z` and 2FA. Only the maintainer can push release tags.

## This website

```bash
cd site
npm install
npm run dev       # http://localhost:5173
npm run verify    # sync, typecheck, content checks, build
```

Pages are MDX files in `site/src/docs/content/`. The changelog page is generated from `CHANGELOG.md`.
