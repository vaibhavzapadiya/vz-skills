## Run it locally

```bash
git clone <this repo> && cd VZ-skills
npm test                                     # all suites, no installs, no network
claude plugin validate ./plugins/vz-skills --strict
claude --plugin-dir ./plugins/vz-skills      # try it in a session
```

## Layout

```text
plugins/vz-skills/    the installable plugin
  skills/<group>/<name>/SKILL.md   groups: entry, lifecycle, specialists, productivity
  agents/  hooks/  policy/  references/  schema/  scripts/  evals/
bin/                  the npx installer
tests/  fixtures/     the test suites and sample repositories
docs/                 documentation, decision log, config examples
site/                 this website
```

## Rules

- Keep each `SKILL.md` under about 200 lines. Put detail in `references/`.
- No new runtime dependencies without an entry in `docs/decisions.md`.
- A script change needs a test. A bug fix needs a regression test.
- After changing skill frontmatter, run `node scripts/gen-catalog.js`. After changing the config schema, run `node scripts/gen-config-schema.js`. `npm test` fails if either is stale.

## Add a skill

1. Create `plugins/vz-skills/skills/<group>/<name>/SKILL.md`. The folder name is the skill name.
2. If you add a new group folder, list it in the `skills` array of `plugin.json`. Without that, its skills silently do not load.
3. Run `node plugins/vz-skills/scripts/vz-validate.js plugins/vz-skills` and `node scripts/gen-catalog.js`.
4. Add the skill to `site/src/data/skills.ts`. `npm run check` in `site/` fails if it is missing.

## Release

Update the version in `plugin.json` and `package.json`, add a `CHANGELOG.md` entry, then run `npm test`, `claude plugin validate ./plugins/vz-skills --strict`, and `npm run package`. Publishing to npm is the owner's step.

## This website

```bash
cd site
npm install
npm run dev       # http://localhost:5173
npm run verify    # sync, typecheck, content checks, build
```

Pages are MDX files in `site/src/docs/content/`. The changelog page is generated from `CHANGELOG.md`.
