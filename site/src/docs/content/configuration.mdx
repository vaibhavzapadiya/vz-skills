<Lead>
You only need one setting: the profile. Every other key is optional.
</Lead>

## Where settings live

| File | Applies to |
|---|---|
| `<project>/.vz-skills/config.json` | This repository. Commit it. |
| `~/.vz-skills/config.json` | All your projects |
| `VZ_SKILLS_PROFILE` environment variable | The profile only, for this shell |

The profile is picked as environment, then project, then user, then the default. The profile sets a preset for every other key. Keys you write yourself override the preset, and the project file wins over the user file.

Create the project file with `/setup BALANCED`, or by hand:

```json title=".vz-skills/config.json"
{
  "version": 1,
  "profile": "BALANCED",
  "hooks": { "protected_paths": ["migrations/**", "infra/**"] }
}
```

See where each value comes from, and compare the profiles:

```bash
node plugins/vz-skills/scripts/vz-config.js --explain --project .
node plugins/vz-skills/scripts/vz-config.js --profiles
```

## All keys

"preset" means the value comes from the profile. Unknown keys and bad values are errors with a suggested fix, never silently ignored.

| Key | Allowed values | Default |
|---|---|---|
| `version` | `1` | 1 |
| `profile` | `FAST`, `BALANCED`, `PRODUCTION` | BALANCED |
| `planning.depth` | `minimal`, `standard`, `detailed` | preset |
| `planning.plan_when` | `never`, `risk>=high`, `risk>=medium`, `risk>=low`, `always` | preset |
| `clarification.ambiguity_tolerance` | `low`, `medium`, `high` | preset |
| `clarification.ask_before_implementing` | `auto`, `always`, `never` | preset |
| `testing.strategy` | `targeted`, `affected`, `full` | preset |
| `testing.require_baseline` | true or false | preset |
| `testing.tdd` | `auto`, `always`, `never` | preset |
| `testing.require_new_tests_for_new_behavior` | true or false | preset |
| `review.depth` | `quick`, `standard`, `thorough` | preset |
| `review.independent_reviewer` | `auto`, `always`, `never` | preset |
| `security.review_trigger` | `sensitive-paths`, `material-changes`, `always` | preset |
| `security.threat_model_on_production` | true or false | true |
| `documentation.expectation` | `none`, `touched-files`, `feature-level` | preset |
| `conventions.notes` | text, up to 2000 characters | empty |
| `conventions.commit_style` | `project`, `conventional`, `freeform` | project |
| `conventions.extra_instructions_file` | a path inside the project | empty |
| `response.style` | `concise`, `standard`, `detailed` | preset |
| `response.final_report` | `summary`, `evidence-table`, `full` | preset |

## Safety floors

Three keys cannot be lowered by accident: `hooks.command_guard`, `hooks.write_guard` and `verification.require_evidence_labels`. Setting one lower is an error. To lower it on purpose, name it in `safety.acknowledged_overrides` in your own user file:

```json title="~/.vz-skills/config.json"
{
  "version": 1,
  "hooks": { "command_guard": "off" },
  "safety": { "acknowledged_overrides": ["hooks.command_guard"] }
}
```

It is then applied, and every session start prints a `SAFETY DOWNGRADE` warning.

<Callout kind="warning" title="Only you can turn a guard off">
An acknowledgment in a repository's `.vz-skills/config.json` is ignored with an error, and the guard stays on. A repository you cloned must not be able to switch off the checks that protect you from it. If a project file has its own `safety.acknowledged_overrides` list, it replaces yours, so the key must be in both.
</Callout>

PRODUCTION also refuses values below its own minimums, unless acknowledged the same way. Those can be acknowledged in the project file too.

`conventions.notes` and `conventions.extra_instructions_file` are style guidance. They cannot allow anything the core policy restricts.

## A typo, as you will see it

```text
ERROR: ... unknown key "profil" (did you mean "profile"?).
ERROR: ... "review.depth" = "Thorough" is not allowed; use one of "quick", "standard", "thorough" (case matters: did you mean "thorough"?)
```

## Editor help

A JSON Schema ships at `plugins/vz-skills/schema/config.v1.schema.json`. Point `$schema` at it for completion and error markers in your editor. Without a local copy, use `https://raw.githubusercontent.com/vaibhavzapadiya/vz-skills/main/plugins/vz-skills/schema/config.v1.schema.json`, which follows `main`. The resolver ignores `$schema`. Examples are in `docs/examples/` in the repository.
