## General

### Does VZ Skills replace Claude Code's permissions or sandbox?

No. Claude Code's permissions and sandbox are the security boundary. VZ hooks can ask, deny, or stay silent, and they fail open. Nothing in VZ configuration can grant what Claude Code forbids. See [Security](/docs/security).

### Is it better than plain Claude Code?

Unknown. No comparison has been run, and no superiority claim is made. The method for measuring it is in `docs/testing-and-evaluation.md` in the repository: the shipped eval cases with `--ablation with-without --runs 3`, with the sample size disclosed. See [Limitations](/docs/limitations).

### Which versions and platforms work?

Claude Code 2.1.233 or later (2.1.259 or later recommended) and Node.js 18 or later. CI runs Ubuntu and Windows on Node 18 and 22. Claude Code is the only supported runtime.

### What does it cost per session?

The session brief adds the core policy, your profile summary, and a short discovery to each session. `claude plugin details` reported about 1,772 always-on tokens for 0.1.0. Hook calls take typically 100-300 ms each. There are no network calls.

## Install

### Why do commands start with `/vz-skills:`, and how do I get plain `/plan`?

Claude Code namespaces every plugin's commands. Run `npx vz-skills install --flat` instead. See [Installation](/docs/installation).

### Why is it `/vz-status` and not `/status`?

A skill named `status` would replace Claude Code's built-in `/status`. The flat installer renames it. `/review` is allowed to replace the bundled review command.

### Can I install it for one project only?

Yes. Add `--scope project` to commit the install in `.claude/` for your team, or `--scope local` for yourself in one repository. Project-scope hooks use `${CLAUDE_PROJECT_DIR}`, so the result is portable.

### The npm command fails because the package does not exist.

The `vz-skills` package has not been published yet. Run `npm pack` in a clone and then `npx --yes ./vz-skills-0.1.0.tgz install --flat`, or use `claude --plugin-dir ./plugins/vz-skills`.

## Behaviour

### Does discovery run my project's scripts?

Not by default. With `--baseline` it runs one allowlisted test command, such as `npm test`, `pytest`, or `go test ./...`. Anything else is `BLOCKED` with the reason. See [Discovery](/docs/discovery#the-baseline).

### Will it read my `.env` file?

VZ scripts never open `.env` files, keys, or tokens. The write guard and command guard ask before touching them. See [Hooks and guards](/docs/guards).

### What happens to my uncommitted changes?

They are listed at discovery and left alone. `implement` does not edit them unless a slice requires it, and then says so first. `verify` confirms they are byte-identical to before.

### Why does it say `UNKNOWN` instead of just guessing?

Because a guessed command is how an unrun test becomes a reported pass. Tell the skill the command, or add a script to your manifest. See [Concepts](/docs/concepts#evidence-labels).

### A one-line fix triggered a lot of ceremony.

The router should skip most steps for a clear, low-risk change. If a path matches `auth|login|session|token|payment|migration|infra|deploy` or a protected path, the tier is high regardless of size. For lighter rigor everywhere else, use `FAST`.

## Configuration

### How do I change the profile?

Run `/setup FAST`, `/setup BALANCED`, or `/setup PRODUCTION` to create `.vz-skills/config.json`. For one shell, set `VZ_SKILLS_PROFILE`. See [Configuration](/docs/configuration).

### Can I turn the guards off?

Yes, deliberately. `hooks.command_guard`, `hooks.write_guard`, and `verification.require_evidence_labels` have floors. Lowering one is an error until it is listed in `safety.acknowledged_overrides`, and every session then prints a warning. The session brief can be disabled without that step.

### My config is rejected with an unknown key.

Unknown keys are errors on purpose, so a typo cannot silently change behaviour. The message includes a suggestion. Check `node plugins/vz-skills/scripts/vz-config.js --explain --project .`.

### Does Claude Code read `.vz-skills/config.json`?

No. Only VZ scripts and skills do. It lives outside `.claude/` because Claude Code reads `.claude/settings.json` for its own settings and would ignore foreign keys there.
