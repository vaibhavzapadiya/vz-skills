## `npx vz-skills`

```text
install [--flat] [--scope user|project|local] [--force]
update [--flat] [--scope ...]
uninstall [--flat] [--scope ...] [--purge]
try                  start Claude Code with the plugin for one session
doctor               check Node, Claude Code, the install, and your config
path                 print the plugin folder
validate             run the official plugin validator
```

`install` needs `claude` on your `PATH`. `--force` works only with `--flat`: it replaces an existing skill or agent of the same name that VZ did not create, after copying it to `vz-skills-backups/`. `--purge` also removes the marketplace and the managed copy, and cannot be combined with `--flat`.

Use the same `--scope` for `update` and `uninstall` that you used for `install`. `update --flat` finds a user-scope flat install on its own. `--scope x`, `-s x` and `--scope=x` all work.

Flags are checked per command. An unknown or misspelled flag exits with `2` and runs nothing. `-h` or `--help` after a command prints the help instead of running it.

Set `CLAUDE_CONFIG_DIR` to test an install against a separate settings folder.

## Scripts in the plugin

Run these from a clone, or from the folder that `npx vz-skills path` prints.

```bash
node scripts/vz-discover.js [folder] [--format json|md] [--run-baseline]
node scripts/vz-config.js [--explain | --profiles | --schema] [--project <dir>]
node scripts/vz-config.js --init [FAST|BALANCED|PRODUCTION]   # any case
node scripts/vz-config.js --validate <file>
node scripts/vz-validate.js [plugin folder]
```

| Script | Use it to |
|---|---|
| `vz-discover.js` | Print what discovery sees. `--run-baseline` runs the test command once, if it is on the safe list. |
| `vz-config.js` | Show settings and where they come from, create a config file, or validate one. |
| `vz-validate.js` | Check the plugin's own structure. |

Exit codes: `0` is fine, `1` means a configuration error (or a failed step), `2` means a usage error.
