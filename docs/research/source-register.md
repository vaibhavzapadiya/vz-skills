## Licensing and attribution

- All three reference repositories are MIT licensed (observed on their GitHub pages, 2026-10-16). VZ Skills **did not copy** code, prompts, or documentation text from them; it adopted *ideas* (a routing meta-skill, user- vs model-invoked split, evidence-before-claims, a per-repo setup entry point) which are not subject to copyright. No attribution obligation is therefore triggered, but the projects are credited in `docs/research/gap-analysis.md` as prior art.
- VZ Skills itself has **no license file yet**: the kit's `LICENSE-NOTICE.md` says the project owner chooses the license. Recorded as open decision DEC-010.
- Runtime dependencies: none beyond Node.js (which Claude Code already requires) and git (optional, for status detection).

## Unresolved research questions

1. Whether `claude plugin eval` behaves per the docs on CLI 2.1.259 (docs state >= 2.1.269). Resolution: run a minimal case and record the result (Phase 9).
2. Exact `name` length limit for skills (docs list forbidden characters only). Resolution: VZ validator enforces <= 64 chars lowercase kebab-case, stricter than the platform.
3. Whether `onFailure: "block"` (>= 2.1.295) is honored on 2.1.259. Resolution: hooks are designed to fail open and this is documented; `onFailure` is not relied upon.
